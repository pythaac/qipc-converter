# 검증 기록

검증일: 2026-11-07. Windows x64, .NET Framework, 포함된 FFmpeg 7.1 사용.

Windows 기본 PowerShell 5.1에서 제공된 `build.ps1`로 단일 EXE와 테스트 실행 파일을 다시 빌드하는 데 성공했습니다. 빌드 스크립트는 한글 경로가 PowerShell 5.1에서도 올바르게 해석되도록 UTF-8 BOM을 사용합니다.

## 자동 테스트

`artifacts/QipcConverter.Tests.exe`: 25개 검사 통과.

- 영상/음성 패킷 경계, JPEG 썸네일, 녹화 인덱스, 오래된 미사용 영역.
- 음성 없는 녹화, 알 수 없는 BIN/프레임 형식, 잘못된 길이, 잘린 인덱스, 변경된 원본 탐지.
- 15/20/30fps 자동 판별, 한 파일 내 15/20fps 전환 시 구간 바이트 범위와 재생 길이.
- 하위 폴더 재귀 탐색, 대소문자 BIN 확장자, 중복 입력 제거.
- 수정 날짜를 사용한 이름, 출력 폴더/파일 드롭 해석, 복수 출력 경로 거부.
- 동시 저장 경쟁과 `_2`, `_3` 이름 충돌 처리. 기존 파일 보존.
- 한글/공백/끝 역슬래시를 포함한 Windows 명령 인자.
- 실제 Windows Forms FileDrop 이벤트 핸들러 호출로 입력 하위 폴더 추가, 출력 파일/폴더 선택, 변환 버튼 활성화.

## 실제 데이터 및 실행 화면

단일 EXE를 실행하여 입력의 ‘파일 찾기’와 출력의 ‘폴더 찾기’ 대화상자, 수정 날짜 표시, 중복 이름 미리보기, 변환 버튼을 확인했습니다. 두 파일을 선택해 실제 앱의 배치 변환을 실행했습니다.

| 입력 | 프레임 | 최종 영상 길이 | 결과 |
|---|---:|---:|---|
| qipc_00000.bin | 26,430 | 29분 22초 | 원본 해상도 HEVC/AAC MP4, 전체 디코딩 통과 |
| qipc_00115.bin | 23,830 | 약 20분 44.23초 | 20→15→20→15fps 구간 연결, 전체 디코딩 통과 |

두 결과의 영상 해상도는 2880×1620입니다. 첫 파일은 기존 결과가 있는 상태에서 `2025-04-04_19-21-26_2.mp4`로 저장됐고, 기존 결과도 그대로 남았습니다. 마지막 파일은 `2025-05-10_17-05-54.mp4`로 저장됐습니다. 파일 이름은 검증 PC의 Windows 탐색기 수정 날짜와 일치합니다.

마지막 파일의 구간은 19,845프레임@20fps, 464프레임@15fps, 821프레임@20fps, 2,700프레임@15fps입니다. 별도 읽기 전용 분석으로 계산한 총 길이 1244.233333초와 최종 MP4의 길이가 일치했습니다.

`qipc_00001.bin`도 24,150프레임, 805블록, AAC 25,154패킷을 정상 추출했습니다. 폴더 전체 116개를 일괄 변환한 것은 아닙니다.

엔진은 `-xerror -err_detect explode`로 전체 영상과 음성을 검사하고, 추출/MP4/디코딩의 프레임 수를 대조한 뒤에만 최종 출력 파일을 만듭니다. 테스트한 입력 원본은 수정하지 않았으며 첫 파일의 변환 전후 SHA-256도 같았습니다.

검증한 환경 외의 Windows 버전, 카메라 모델, 모든 BIN 변형에 대한 동작을 보장하지 않습니다. macOS 빌드는 없습니다.
